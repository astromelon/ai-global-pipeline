# 오류 원인 찾기 + 근본 수정

요청 내용: $ARGUMENTS
(비어 있거나 `$ARGUMENTS` 그대로 보이면 호출 메시지에서 이 스킬 이름 뒤의 내용을 요청으로 본다.)

요청에서 다음 항목을 찾는다: 기대 동작, 실제 현상, 오류 메시지, 관련 파일, 재현 단계, 이전에 고친 방법. 빠진 항목이 원인 추적에 꼭 필요하면 무엇이 필요한지 구체적으로 묻는다(최대 3개).

1. **재현:** 재현 단계나 테스트로 현상을 직접 확인한다. 재현하지 못하면 그 사실을 적는다.
2. **원인 추적:** 결론을 **증거**(로그, 코드 경로:줄, 실행 결과)와 **추측**으로 나눠 적는다. 증거가 부족하면 추가로 필요한 로그·값을 구체적으로 요청하고, 그 시점에서 멈춘다.
3. **재발 버그:** 이전 수정이 있었다면 그 수정이 왜 원인을 잡지 못했는지 설명한다.
4. **수정 범위 확정 후에는 파이프라인대로 진행한다:** Node 2 브랜치(`fix/...`) → (Claude 는 [Handoff] 로 agy 에 구현 위임 가능) → Node 3 검증 → Node 4 질문.
   - 먼저 **수정 전에 실패하는 회귀 테스트**를 쓰고 실패를 확인한다.
   - 원인만 고친다(관련 없는 정리 금지). 같은 테스트가 통과하는지 확인한다.
5. Node 4 보고에 다음을 넣는다: 원인(증거), 가장 작은 수정과 그게 왜 통하는지, 회귀 테스트 이름과 수정 전 실패·수정 후 통과 결과, 사용자가 직접 재현·확인하는 방법.
