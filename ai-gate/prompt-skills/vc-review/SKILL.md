# 합치기 전에 검토하기 (수정 금지)

요청 내용: $ARGUMENTS
(비어 있거나 `$ARGUMENTS` 그대로 보이면 호출 메시지에서 이 스킬 이름 뒤의 내용을 요청으로 본다.)

이번 작업은 **검토만** 한다. 파일 수정, 커밋, 푸시는 하지 않는다.

1. **대상:** 요청에 파일·커밋 범위가 없으면 현재 브랜치와 `main`의 차이(`git diff main...HEAD`)에 작업 트리 변경(`git diff`)을 더한 것을 본다.
2. **의도:** 요청에 의도한 동작이 없으면 커밋 메시지·브랜치 이름·계획서(`git rev-parse --git-path ai-task.md`)에서 찾는다. 찾지 못하면 미확인으로 적는다.
3. **우선순위:** 버그 → 기존 기능 회귀(호출하는 쪽 포함) → 데이터·비밀 노출 → 빠진 실패 처리 → 테스트 공백. 동작·유지보수에 영향 없는 겉모양 취향은 넘긴다.
4. **보고 형식:** 심각도 순으로
   - **확실한 문제:** `파일:줄` / 실제로 문제가 생기는 구체적인 상황(입력·상태 → 잘못된 결과) / 고치는 방법
   - **열린 질문:** 코드만으로 판단할 수 없는 것과 확인 방법
   - 문제가 없으면 "확실한 문제 없음"이라고 쓰고, 확인한 범위를 적는다.
5. 보고 후 멈춘다. 수정은 사용자가 지시할 때 한다.
