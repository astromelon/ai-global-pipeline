# 범위를 정해 기능 만들기

요청 내용: $ARGUMENTS
(비어 있거나 `$ARGUMENTS` 그대로 보이면 호출 메시지에서 이 스킬 이름 뒤의 내용을 요청으로 본다.)

1. **범위 확정:** 요청에서 다음을 정리한다. 답에 따라 구현이 달라지는 항목만 최대 3개 질문한다.
   - 사용자가 하는 동작, 성공하면 나와야 하는 결과
   - 입력값과 검사 규칙(서버에서도 다시 검사할 항목 표시)
   - 로딩·빈 결과·실패·성공 상태가 각각 어떻게 보여야 하는지
   - 완료 확인 체크리스트(3~6개)
2. **파이프라인대로 구현한다:** Node 1 브리핑 → Node 2 브랜치(`feat/...`) → (Claude 는 [Handoff] 로 agy 에 구현 위임 가능, 위 체크리스트를 계획서 `# 구현 지시`에 넣는다) → Node 3 검증 → Node 4 질문.
   - 기존 구조·스타일·이미 설치된 도구를 재사용하고 필요한 부분만 바꾼다.
   - 새 의존성은 꼭 필요할 때만 추가하고 이유를 밝힌다.
   - 비밀 값은 브라우저 코드·로그에 넣지 않고 설정 자리표시자로 둔다.
3. Node 4 보고에 다음을 넣는다: 바뀐 파일 목록, 체크리스트별 확인 결과, 사용자가 화면에서 직접 확인하는 방법, 미확인/미실행 항목.
