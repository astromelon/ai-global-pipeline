# 느린 동작 고치기 (측정 기반)

요청 내용: $ARGUMENTS
(비어 있거나 `$ARGUMENTS` 그대로 보이면 호출 메시지에서 이 스킬 이름 뒤의 내용을 요청으로 본다.)

1. **상황 정리:** 어떤 상황에서 어떤 페이지·동작이 얼마나 느린지(측정값이 있으면 그대로) 적는다.
2. **병목 후보:** 코드와 측정값을 근거로 후보를 **증거가 강한 순서**로 정리한다. 후보마다 근거(측정값, 쿼리 수, 로그, 코드 경로:줄)와 추측을 나눈다. 부족한 측정값은 무엇을 어떻게 재면 되는지 적는다.
3. **기준 측정:** 수정 전에 재현 가능한 같은 조건(데이터·요청·반복 횟수)으로 기준값을 잰다. 측정할 수 없으면 그 이유를 적고, 근거가 약한 수정은 하지 않는다.
4. **수정은 파이프라인대로:** Node 2 브랜치(`fix/` 또는 `refactor/`) → 동작을 바꾸지 않는, 근거가 가장 확실한 수정 1개 → Node 3 검증(기존 테스트로 동작 유지 확인) → 같은 조건으로 재측정 → Node 4 질문.
5. Node 4 보고에 전후 측정값(조건 포함)을 표로 넣는다. **실제로 측정된 경우에만 빨라졌다고 말한다.** 측정하지 못한 부분은 "미측정"으로 표시한다.
